# Feature Proposal: Collaboration & Secure Project Sharing

## 1. Summary

La fonctionnalité **Collaboration & Secure Project Sharing** introduit un véritable modèle d’ownership et de partage de projets dans Econ Graph. Elle corrige la faiblesse actuelle (projets non protégés ou non structurés par utilisateur) et permet :

* une **sécurité correcte** (auth obligatoire, owner explicite),
* un **partage contrôlé** (lecture seule, édition, co-construction),
* une base saine pour des fonctionnalités futures (équipes, organisations, permissions avancées).

C’est une brique structurante pour faire passer Econ Graph d’un outil individuel à une **plateforme d’équipe**.

---

## 2. Goals

* Protéger les projets par un owner explicite.
* Permettre de partager un projet avec d’autres utilisateurs en mode **viewer** ou **editor**.
* Préparer le terrain à des espaces d’équipe / d’organisation.
* Aligner l’API avec les meilleures pratiques de sécurité (auth systématique).

---

## 3. User Stories

### ● Utilisateur individuel

> "Je veux que mes projets soient privés par défaut et impossibles à modifier ou lire par d’autres sans mon accord."

### ● Consultant / Freelance

> "Je veux partager un projet avec un client : il peut le voir, mais pas casser le modèle."

### ● Équipe (startup, cabinet de conseil, service finance)

> "Nous voulons travailler à plusieurs sur les mêmes modèles : certains peuvent éditer, d’autres seulement visualiser."

### ● Enseignant

> "Je veux dupliquer un projet template pour chaque promo, et éventuellement donner des droits d’édition à des collègues."

## 4. Functional Specification

### 4.1 Ownership de projet

* Nouveau champ DB : `projects.owner_id` (FK vers users.id).
* Les projets sont **privés par défaut** : seuls owner et collaborateurs peuvent y accéder.

### 4.2 Rôles de collaboration

Deux niveaux simples pour la V1 :

* **Viewer** :

  * Peut ouvrir le projet en lecture.
  * Peut naviguer dans le graphe, changer de scénario.
  * Ne peut pas éditer les nœuds, le code, ni les overrides.
  * Peut commenter (option V2).

* **Editor** :

  * Peut tout modifier dans le projet (modèle, scénarios, composites instanciés).
  * Ne peut pas changer l’owner.

### 4.3 Gestion du partage

Depuis le projet, un panneau "Share" permet :

* de voir la liste des collaborateurs actuels,
* d’ajouter un utilisateur par email/username,
* de choisir son rôle (Viewer / Editor),
* de retirer des accès.

### 4.4 Public Links

Articulé avec le **Public Viewer Mode** (feature 1) :

* Possibilité de générer un **lien public** read-only (token).
* Ce lien est indépendant de la liste des collaborateurs.
* Option : rotation / révocation du lien public.

### 4.5 Permissions de base (V1)

| Action                               | Owner | Editor | Viewer | Public Link |
| ------------------------------------ | :---: | :----: | :----: | :---------: |
| Voir le projet                       |   ✔   |    ✔   |    ✔   |      ✔      |
| Modifier les nœuds                   |   ✔   |    ✔   |    ✖   |      ✖      |
| Modifier les scénarios               |   ✔   |    ✔   |    ✖   |      ✖      |
| Modifier les composites instanciés   |   ✔   |    ✔   |    ✖   |      ✖      |
| Modifier la liste des collaborateurs |   ✔   |    ✖   |    ✖   |      ✖      |
| Générer / révoquer un lien public    |   ✔   |    ✖   |    ✖   |      ✖      |

## 5. Technical Architecture

### 5.1 Backend

1. **Modèle de données**

   * Table `projects` : ajout de `owner_id`.
   * Nouvelle table `project_collaborators` :

     * project_id (FK)
     * user_id (FK)
     * role ("viewer" | "editor").

2. **Sécurisation des endpoints**

   * Tous les endpoints `/projects` (`GET`, `POST`, `PATCH`, `DELETE`) doivent utiliser `get_current_user`.
   * Règles d’accès :

     * `GET /projects/{id}` : owner + collaborateurs.
     * `PATCH /projects/{id}` : owner + editor.
     * `DELETE /projects/{id}` : owner seulement.

3. **Gestion du lien public**

   * Champ `public_view_token` optionnel sur `projects`.
   * Endpoint `POST /projects/{id}/public-link` : crée / régénère.
   * Endpoint `DELETE /projects/{id}/public-link` : révoque.
   * Endpoint `GET /viewer/{token}` : utilise `public_view_token`.

### 5.2 Frontend

* `SharePanel.tsx` :

  * Liste des collaborateurs.
  * Formulaire d’ajout (email/username + rôle).
  * Boutons de suppression.

* `PublicLinkSection.tsx` :

  * Affichage lien courant.
  * Bouton Generate / Regenerate.
  * Bouton Revoke.

* Guards de navigation :

  * Redirection si l’utilisateur n’a pas accès.

---

## 6. UX Flow

### 6.1 Création de projet

1. L’utilisateur authentifié crée un projet.
2. Il en devient automatiquement **owner**.

### 6.2 Ajout d’un collaborateur

1. Bouton "Share" dans la top bar.
2. Champ "Add collaborator" → email/username.
3. Sélection du rôle (Viewer/Editor).
4. Envoi d’une invitation (option V2) ou ajout direct.

### 6.3 Utilisation du lien public

1. L’owner génère un lien public.
2. Il le partage (Slack, email, LMS…).
3. Un viewer externe ouvre une vue read-only.

---

## 7. KPI / Metrics

* Nombre de projets avec au moins 1 collaborateur.
* Nombre moyen de collaborateurs par projet.
* Nombre de liens publics actifs.
* Taux d’accès par des viewers externes.

---

## 8. Roadmap

### Phase 1 — Sécurité de base (2 jours)

* Ajout owner_id + enforcement get_current_user sur les endpoints projets.
* Verrouillage complet : plus de projets publics par accident.

### Phase 2 — Collaborateurs (3 jours)

* Modèle `project_collaborators`.
* API + panel de partage simple.

### Phase 3 — Lien public (2 jours)

* Token + viewer intégré avec la Feature 1.

### Phase 4 — V2 Collaboration (3–4 jours)

* Invitations par email.
* Historique des modifications.
* Commentaires / annotations.

---

## 9. Risques & Limitations

* Migration de données existantes (projets sans owner).
* Définir un comportement clair pour les projets legacy.
* Gestion future des organisations / workspaces à anticiper dans le schéma.

---

## 10. Impact stratégique

Cette feature :

* corrige une faiblesse critique (auth manquante sur les projets),
* ouvre la voie à un usage en équipe,
* supporte le modèle "créateur → viewer externe",
* prépare des offres B2B (équipe, organisation, éducation).

En clair, elle fait passer Econ Graph du statut de **tool personnel avancé** à celui de **plateforme collaborative de modélisation**.
