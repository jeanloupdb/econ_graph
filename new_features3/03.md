# Feature Proposal: Composite Library & Modular Editor

## 1. Summary

La **Composite Library** introduit un système complet permettant de créer, organiser, utiliser et partager des sous-graphes réutilisables sous forme de "briques logiques". Cette fonctionnalité transforme Econ Graph en un écosystème modulaire comparable à un **Figma des modèles**, où les utilisateurs composent leurs projets grâce à un catalogue de modules intelligents.

Cette évolution donne une existence concrète et visible aux composites (déjà très avancés côté backend), en les intégrant dans un workflow fluide et naturel.

---

## 2. Goals

* Rendre les composites simples à créer, visualiser, éditer et réutiliser.
* Permettre la construction rapide de modèles complexes via des briques standardisées.
* Favoriser le partage interne (équipe) et externe (communauté).
* Transforme Econ Graph en une plateforme "lego" pour la modélisation économique, pédagogique et analytique.

---

## 4. Functional Specification

### 4.1 Composite Library (UI)

Nouvel espace dédié accessible via la sidebar : **Library**.

Contient :

* Liste de tous les composites
* Aperçu miniature du sous-graphe (mini-map)
* Métadonnées : nom, description, tags
* Boutons : Edit, Duplicate, Delete

### 4.2 Composite Usage

Depuis un projet, l’utilisateur peut :

* Ouvrir la Library
* Glisser-déposer un composite dans le canvas
* Voir apparaître un nœud composite instancié

### 4.3 Composite Editor

Nouvel éditeur dédié, séparé du canvas principal :

* Zoom/pan
* Création de nœuds internes
* Définition des **Exposed Roots** (inputs visibles depuis le projet parent)
* Tests unitaires internes

### 4.4 Exposed Roots Panel

Un paneau latéral permet de :

* Marquer un nœud comme "root exposé"
* Lui donner un label public (ex: "Revenue Initial")
* Définir les contraintes / unités / documentation

### 4.5 Versioning (optionnel V2)

* Historique des modifications d’un composite
* Boutons : Preview / Rollback

### 4.6 Import & Export

* Export JSON d’un composite
* Import dans un autre projet / autre compte

## 5. Technical Architecture

### Backend

1. **Endpoints existants à compléter** :

   * `POST /composites`
   * `PATCH /composites/{id}`
   * `GET /composites`
   * `GET /composites/{id}`

2. **Nouveaux endpoints proposés** :

   * `/composites/{id}/preview` → miniature du graphe
   * `/composites/{id}/exposed-roots` (gestion avancée)
   * `/composites/tags` pour classification

3. **Graph transformations**

   * Conversion composite <→ instance
   * Synchronisation automatique lors d’une édition

### Frontend

* Nouveau layout : **CompositeEditor.tsx** (à finaliser)
* LibraryPanel.tsx : navigation, tags, search
* Drag & Drop vers le canvas
* MiniMap-preview pour chaque composite

## 6. UX Flow

### Création d’un composite

1. L’utilisateur sélectionne plusieurs nœuds dans son projet.
2. Bouton "Create Composite".
3. Nom + description + tags.
4. Le composite est créé et les nœuds déplacés dans un nouvel espace éditeur.

### Utilisation d’un composite

1. Library → choisir un composite.
2. Drag → drop vers canvas.
3. Un nœud composite apparaît.
4. Les exposed roots deviennent visibles dans la Node Sheet.

### Édition d’un composite

1. Library → bouton Edit.
2. Ouverture de l’éditeur dédié.
3. Modifications internes.
4. Sauvegarde synchronisée pour toutes les instances.

## 8. Roadmap

### Phase 1 — Library (2 jours)

* UI liste + preview + actions
* Gestion tags et recherche

### Phase 2 — Composite Editor (3 jours)

* Canvas dédié
* Gestion exposed roots
* Mini-map

### Phase 3 — Integration Project (2 jours)

* Drag & drop depuis Library
* Instanciation propre dans un projet

### Phase 4 — V2 (2–3 jours)

* Versioning
* Import/export
* Documentation intégrée

---

## 9. Risques & Limitations

* Complexité du maintien de la synchro instances ↔ composite
* Risque de casser des projets en modifiant un composite partagé
* Besoin de règles d’override spécifiques

---

## 10. Impact stratégique

La **Composite Library** transforme Econ Graph en un véritable environnement modulaire :

* productivité accrue,
* standardisation des modèles,
* pédagogie simplifiée,
* adoption en équipe,
* création d’un écosystème de modèles.

C’est une brique essentielle pour positionner Econ Graph comme **l’outil de modélisation économique visuel le plus moderne du marché**.
